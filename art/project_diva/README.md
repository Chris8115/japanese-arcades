# Project DIVA Arcade Future Tone cabinet

Project DIVA Arcade Future Tone is the seventh cabinet in the **Japanese
Arcades** creative tab. It shares the other cabinets' three-part placement and
native Minecraft music-disc playback. The model follows the supplied Future
Tone cabinet photographs: the broad geometric topper, two vertical speaker
pods, separate logo sign, deeply raked landscape display, luminous touch slider,
and four large symbol buttons above the black service-door base.

The cabinet occupies **three vertical blocks**, with a physical envelope of
about **1.26 blocks wide**, **1.45 blocks deep**, and **2.98 blocks tall**. Leave
side clearance for the topper and front clearance for the projecting control deck. Dimensions are
interpreted from the photographs rather than manufacturer measurements.

The display, slider, buttons, and card reader are decorative. Minecraft music
discs provide the playable audio; the cabinet does not run the Project DIVA
rhythm game. The base emits light level 4 and both upper sections emit level 13.

## Use in Minecraft

Launch `dev.cmd Client` or `dev.cmd PackClient`, then select **Project DIVA Arcade
Future Tone Cabinet** from **Japanese Arcades**, or run:

```text
/give @s japanesearcades:project_diva
```

Place it on a solid floor with three clear vertical blocks. Its front faces the
player. Breaking any section removes all three; survival drops one cabinet item.

Right-click any section with a music disc to insert it and start playback.
Right-click again to eject it. Each cabinet stores one disc and saves its playback
progress. Modded songs with a valid jukebox-playable component use the same native
player. Breaking the cabinet stops the song and returns its disc once, including
in creative mode. Adjacent cabinets retain independent discs and playback. The
base provides jukebox redstone/comparator output and a one-slot container.

The ejection position is 1.16 blocks forward of the base center to keep the
entire dropped disc clear of collision. A shallow top ledge covers the underside
of the projecting deck without filling the open space beneath it. Restart the
development client after Java changes; F3+T reloads only
models and textures.

The five shared textures combine manufactured prints with the two original
illustrations. The button order and colors follow the references: green
triangle, pink square, blue cross, and red circle. White/cyan light rails frame
the screen; the upper board combines Miku's flat teal silhouette with magenta,
yellow, blue, and pale silver graphics. The paired speaker pods contain black
double-lobed grilles and turquoise linework. Small hardware includes a yellow
start button, headphone jack, coin opening, Aime card-reader panel, service-door
locks, rear vents, castors, and a folded metal toeplate.

The two illustrations were produced in **built-in image generation mode**.
Their original pixels remain unchanged in the saved source PNGs and are padded
onto power-of-two runtime textures without resampling. Exact prompts and
provenance are saved in [imagegen-prompts.txt](imagegen-prompts.txt). The material,
hardware, instructions, symbols, and branding atlases are generated by
`scripts/project_diva_textures.py`.

Regenerate with Python and Pillow, then render with Blender:

```powershell
python scripts/make_project_diva_model.py
blender --background --python scripts/render_project_diva_model.py
```

The generator uses `scripts/project_diva_shell_geometry.py` and
`scripts/project_diva_upper_geometry.py`. A shared surface pass removes hidden
faces and clips overlapping opaque surfaces. All parts use native cuboids and
per-face full-bright data, with no custom renderer.

The final export contains **4,373 elements and 5,680 rendered faces**, divided
among the base, console, and marquee models. Some exported cuboids retain only
their visible face fragments, so element count is not polygon count. The display
uses its original aspect ratio, and the separate touch slider remains visible
behind the four buttons on the extended control tray.

The renderer reads the exported game geometry and texture atlases, produces
`project_diva-{front,back,side,controls,screen,marquee}.png`, and saves the packed
Blender scene. Append `-- --front-only` for a front preview or `-- --detail-only`
for controls, screen, and marquee views. Studio lighting differs from Minecraft.

The generator is the canonical model source. Save manual Blockbench edits
separately or transfer them into the generator before regeneration replaces the
exported model files.

## Runtime implementation

The block/item ID is `japanesearcades:project_diva`. Registration begins in
`src/main/java/local/japanesearcades/JapaneseArcades.java`.
`ProjectDivaCabinetBlock.java` defines section bounds and disc-ejection position.
It inherits placement and interaction from `NostalgiaCabinetBlock.java`. All
cabinets share `NostalgiaJukeboxBlockEntity.java` and Minecraft's native
`JukeboxSongPlayer`, retaining the existing saved-data and block-entity IDs.

## Runtime verification

Four Project DIVA integration tests exercise actual placement and interaction
through every section, single-drop removal, saved-disc placement and playback
restoration, creative removal beside an independently playing MÚSECA, and rotated
deck/topper selection, clearance under the shallow deck ledge, and the newly
ejected disc's full bounding box clear of every cabinet section and world collision.

The final release build succeeded and all **30 native integration tests passed
on 2026-10-06**, including the four new Project DIVA tests and the existing
twenty-six. Logs are `build/verification/project-diva-final-build.log` and
`build/verification/project-diva-final-gametest.log`.

The release-jar audit checked all seven cabinets' twelve blockstate variants,
section and item models, textures, and loot. All **84 resource files** matched
their source files, and all **23 compiled Java classes** matched their compiled
output with Java 21 bytecode. Project DIVA's language entry and pickaxe tag are
included. No authoring files or nested mod jars are packaged. The report is
`build/verification/project-diva-package-audit.json`.

These server and package checks do not verify in-world appearance or full-pack
client compatibility. Studio views use the exported runtime geometry and UVs.
The final studio views were reviewed for the visible touch slider, button order,
sloped instruction panel, silhouette header, and connected side profile. Native
geometry/UV checks pass with no same-facing coplanar overlaps involving rotated
surfaces. The model contains 4,373 elements and 5,680 visible faces after the
opaque surface pass.
